Basics · 01

Selecting columns

Every query starts by naming which columns you want, and which table they come from. Use * to grab every column, or list only the ones you need.

SELECT name, city
FROM customers;
Result
namecity
Aarav ShahMumbai
Diya MehtaPune
Kabir NairNavi Mumbai

Add DISTINCT right after SELECT to drop duplicate rows — useful for questions like "which cities do we operate in?"

SELECT DISTINCT city FROM customers;

Basics · 02

Filtering with WHERE

WHERE keeps only the rows that match a condition. It runs before any sorting or grouping.

SELECT order_id, total_amount
FROM orders
WHERE total_amount > 300;

Combine conditions with AND / OR, match text patterns with LIKE (% matches any run of characters), and check ranges with BETWEEN or membership with IN.

SELECT *
FROM products
WHERE category IN ('Dairy', 'Snacks')
  AND price BETWEEN 20 AND 60;

Careful with NULL. A missing value is never "equal" to anything, not even another NULL. Use column IS NULL or column IS NOT NULL instead of = NULL.

Basics · 03

Sorting & limiting

ORDER BY sorts your results; add DESC for highest-to-lowest (the default is ascending). LIMIT caps how many rows come back — handy for "top 5" style questions.

SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 5;

Basics · 04

Aliases

Give a column or table a temporary name with AS — it makes results more readable and is essential once you start joining tables and need short labels to refer back to them.

SELECT name AS product_name, price AS selling_price
FROM products AS p;

The AS keyword is optional — orders o works the same as orders AS o. You'll see the short form everywhere once you get to joins below.

Aggregating · 05

Aggregate functions

Aggregate functions collapse many rows into one summary value: COUNT, SUM, AVG, MIN, and MAX.

SELECT COUNT(*) AS total_orders,
       ROUND(AVG(total_amount), 2) AS avg_order_value
FROM orders
WHERE status = 'Delivered';

Aggregating · 06

GROUP BY & HAVING

GROUP BY buckets rows that share a value, then runs your aggregate functions separately per bucket — e.g. "how many products, and what's the average price, per category?"

SELECT category, COUNT(*) AS items, ROUND(AVG(price), 2) AS avg_price
FROM products
GROUP BY category
ORDER BY items DESC;

WHERE filters rows before grouping; HAVING filters groups after aggregation — use it when your condition involves an aggregate function like COUNT or SUM.

SELECT category, COUNT(*) AS items
FROM products
GROUP BY category
HAVING COUNT(*) > 3;

Joins · 07

What is a JOIN?

QuickCart's data is split across separate tables — customers, orders, dark_stores, products, order_items — so that each fact is stored once. A JOIN stitches rows from two tables back together for a query, matched on a shared value (usually a primary key in one table and a foreign key in the other).

Every join needs an ON clause that says how to match rows:

SELECT o.order_id, c.name, o.total_amount
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
ORDER BY o.total_amount DESC
LIMIT 5;

Here o and c are aliases for orders and customers. The ON clause says: "match each order to the customer whose customer_id equals the order's customer_id." The type of join you pick decides what happens to rows on either side that don't find a match.

INNER JOIN

Keeps only matches

Only rows that exist in both tables come back. Orders with no matching customer (or customers with no orders) are dropped.

The plain JOIN keyword defaults to INNER JOIN — it's the one you'll use most often.

SELECT o.order_id, c.name, s.store_name
FROM orders o
INNER JOIN customers c ON o.customer_id = c.customer_id
INNER JOIN dark_stores s ON o.store_id = s.store_id;

LEFT (OUTER) JOIN

Keeps everything on the left

Every row from the first (left) table is kept, even if nothing matches on the right — unmatched columns come back as NULL.

Perfect for "show me all X, along with any related Y" — including customers who haven't ordered yet.

SELECT c.name, COUNT(o.order_id) AS orders_placed
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.name
ORDER BY orders_placed ASC;

Any customer with zero orders still shows up here, with orders_placed = 0.

RIGHT (OUTER) JOIN

Keeps everything on the right

The mirror image of LEFT JOIN: every row from the second (right) table is kept, matched or not.

SELECT s.store_name, o.order_id
FROM orders o
RIGHT JOIN dark_stores s ON o.store_id = s.store_id;

In practice, most people just swap the table order and write a LEFT JOIN instead — it reads the same way and is supported by more database engines. (Note: SQLite added RIGHT JOIN support in version 3.39 — this Lab's engine supports it.)

FULL OUTER JOIN

Keeps everything, both sides

Combines LEFT and RIGHT: every row from both tables appears, with NULLs wherever there's no match on the other side.

SELECT c.name, o.order_id
FROM customers c
FULL OUTER JOIN orders o ON c.customer_id = o.customer_id;

Useful for spotting mismatches on either side at once — e.g. customers with no orders, sitting in the same result as (hypothetically) orphaned orders with no customer.

CROSS JOIN

Every row × every row

No ON condition — pairs every row from the first table with every row from the second. 4 stores × 20 products = 80 rows.

SELECT s.store_name, p.name
FROM dark_stores s
CROSS JOIN products p;

Rarely used on real data directly, but handy for generating every possible combination — e.g. a full store × product grid to check stock coverage.

SELF JOIN

Not a different keyword — just a regular join where a table is joined to itself, using two different aliases. Useful for comparing rows within the same table.

SELECT a.name AS customer_1, b.name AS customer_2, a.city
FROM customers a
JOIN customers b
  ON a.city = b.city AND a.customer_id < b.customer_id;

This finds pairs of different customers who live in the same city. The a.customer_id < b.customer_id condition stops each pair from being listed twice.

Joining 3+ tables

Chain as many joins as you need — each one just needs its own ON clause. This is how you'd answer "what did each customer actually buy?", pulling from orders, order_items, and products together.

SELECT c.name, p.name AS product, oi.quantity, o.order_time
FROM orders o
JOIN customers c   ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
JOIN products p    ON p.product_id = oi.product_id
ORDER BY o.order_time;

Advanced · 08

Subqueries

A query nested inside another, usually in parentheses. It runs first, and its result is used by the outer query — often with IN, =, or as a stand-in for a table.

SELECT name
FROM customers
WHERE customer_id IN (
  SELECT customer_id
  FROM orders
  WHERE total_amount > 400
);

This finds every customer who has placed at least one order over 400 — without ever writing a JOIN.

Advanced · 09

CTEs (WITH)

A Common Table Expression names a subquery up front with WITH, so you can reference it like a temporary table later in the same statement. Great for breaking a complex query into readable steps.

WITH store_totals AS (
  SELECT store_id, SUM(total_amount) AS revenue
  FROM orders
  WHERE status = 'Delivered'
  GROUP BY store_id
)
SELECT s.store_name, st.revenue
FROM store_totals st
JOIN dark_stores s ON s.store_id = st.store_id
ORDER BY st.revenue DESC;

Advanced · 10

Window functions

Unlike GROUP BY, a window function keeps every row while still letting you compute something across a related set of rows, using OVER (...). PARTITION BY restarts the calculation per group.

SELECT customer_id, order_id, total_amount,
       RANK() OVER (
         PARTITION BY customer_id
         ORDER BY total_amount DESC
       ) AS rank_within_customer
FROM orders;

This ranks each customer's own orders from biggest to smallest, without collapsing the rows the way GROUP BY would.

Advanced · 11

CASE expressions

CASE is SQL's inline if/else — evaluate conditions in order and return the first matching result. Useful for bucketing values on the fly.

SELECT order_id, delivery_minutes,
  CASE
    WHEN delivery_minutes <= 10 THEN 'Fast'
    WHEN delivery_minutes <= 15 THEN 'On time'
    ELSE 'Slow'
  END AS speed_bucket
FROM orders;
